# Apps Script 골격 — 배포 및 확장 가이드

앞서 논의한 "껍데기부터 먼저" 순서대로, **각 단계 페이지를 제외한 전부**를 만들었습니다.

---

## 들어 있는 것

| 파일 | 역할 |
|---|---|
| `00_Config.gs` | 상수 · **단계 정의(STEPS)** · 이미지 용도 |
| `01_WebApp.gs` | 웹앱 진입점 · 클라이언트 API · 진행률 · 교차 검증 |
| `02_Session.gs` | 진입 인증 · 세션 저장/로드 · **스냅샷 · 복원** |
| `03_SheetSync.gs` | 마스터 템플릿 복사 · 탭 동기화 |
| `04_Upload.gs` | 이미지 업로드 · 대표 지정 · 삭제 |
| `05_Notify.gs` | 담당자 메일 알림 |
| `Index.html` | 진입 화면 · 이어하기 · 셸 |
| `Css.html` | 스타일 (PC 스텝퍼 ↔ 모바일 프로그레스 바) |
| `Js.html` | 라우팅 · 자동저장 · 단계 렌더러 |

### 동작하는 것

- 진입 인증 (상호명 + 대표자명 + 뒷 4자리)
- 이어하기 · 자동저장 (10초 디바운스 + 단계 이동 시 강제)
- 스텝퍼 · 단계 이동 · 진행률
- **이미지 업로드** (리사이즈 → 순차 전송 → 드라이브 저장)
- **검토·제출** (필수 점검 · 상담필요 목록 · 메일 발송)
- 스냅샷 저장 · 버전 복원 · 변경분 비교

### 비어 있는 것

**1~9단계 입력 화면**입니다. `기본정보`만 예시로 절반쯤 채워뒀고 나머지는 자리표시자입니다.

## 배포

1. [script.google.com](https://script.google.com) → 새 프로젝트
2. 파일을 옮깁니다

   | 로컬 | Apps Script | 만드는 법 |
   |---|---|---|
   | `*.gs` 6개 | 같은 이름 | `+` → 스크립트 |
   | `Index.html` `Css.html` `Js.html` | 같은 이름 | `+` → HTML |
   | `appsscript.json` | 매니페스트 | ⚙️ 설정 → "매니페스트 파일 표시" 체크 후 편집 |

   > `.gs` 파일명은 편의상 번호를 붙였을 뿐입니다. Apps Script는 모든 파일을 한 스코프에서 실행하므로 이름은 자유입니다.

3. **`00_Config.gs` 상단 3개를 채웁니다**

   ```javascript
   const SESSION_SHEET_ID  = '';   // 비워두면 자동 생성됩니다
   const TEMPLATE_SHEET_ID = '';   // ← 세팅시트 v26을 구글 시트로 변환한 뒤 그 ID
   const NOTIFY_EMAIL      = '';   // ← 담당자 메일
   ```

4. **배포 → 새 배포 → 웹 앱**

   | 항목 | 값 |
   |---|---|
   | 실행 계정 | **나** |
   | 액세스 권한 | **모든 사용자** |

5. 권한 승인 → 나온 URL을 휴대폰에서 열어보세요

## 단계 화면 채우는 법

`Js.html` 아래쪽 `StepRenderers` 에 함수를 하나 추가하면 됩니다.

```javascript
StepRenderers.hours = function(body, data){
  body.appendChild(el('h2','page-h','영업시간'));

  var card = el('div','card');
  card.appendChild(field('정기 휴무', 'text', data['정기 휴무'], {
    hint: '예) 매주 월요일 / 매월 둘째·넷째 일요일'
  }));
  body.appendChild(card);
};
```

`field(라벨, 타입, 현재값, 옵션)` 이 만들어 주는 것

- 입력칸 + `data-f="라벨"` (자동저장이 이 속성을 읽습니다)
- 글자 수 카운터 (`max` 옵션)
- **상태 드롭다운** (입력완료 / 미입력 / **상담필요**)

라벨을 **시트의 항목명과 똑같이** 쓰세요. `03_SheetSync.gs`가 B열 항목명으로 매칭하므로, 이름만 맞으면 행이 밀려도 안전합니다.

### 표 형식 단계 (시술메뉴 · 패키지 · 예약상품)

행 배열을 넘기는 형태입니다.

```javascript
StepCollectors.menu = function(){
  return { rows: [
    // 카테고리 · 시술명 · 소요시간 · 정가 · 가격부가설명 · 시술설명 · 가격표노출 · 순서
    ['바디', '등 관리 60분', 60, 80000, 'VAT 포함', '설명…', 'Y', 1],
    ['바디', '등 관리 90분', 90, 110000, '', '', 'Y', 2]
  ]};
};
```

행 배열은 `03_SheetSync.gs`의 `TAB_SPEC[탭].cols` 순서와 1:1로 맞춥니다.
`writeTable_()`이 각 탭의 시작 행부터 그 열들에만 써 넣습니다.

**자동 계산 열은 배열에 넣지 마세요.** v26 시트는 수식 열이 데이터 열 사이에 끼어 있습니다.

| 탭 | 앱이 쓰는 열 | 건너뛰는 열 |
|---|---|---|
| 03_영업시간 | B~G (5~12행) | A 요일 · H 비고 |
| 04_시술마스터 | B~I (5~44행) | J 사용 현황 |
| 05_패키지 | B~F · H~J (5~24행) | **G 할인율 · K 사용 현황** |
| 06_예약상품 | B~D · F~H · J~P (5~44행) | **E 포함 시술 · I 할인율** |
| 09_이미지 | C~G (6~125 · 130 · 135~174행) | A No · B 구분 · H 비고 |

값이 없는 아래쪽 행은 비웁니다. 사장님이 시술을 지우고 재제출했는데 예전 행이 남아 있으면
담당자가 지운 줄 모르고 그대로 옮겨 심기 때문입니다.

## 설계 원칙이 코드에 반영된 곳

| 원칙 | 위치 |
|---|---|
| 단계 순서를 하드코딩하지 않음 | `00_Config.gs` `STEPS` 배열 |
| 라우팅은 번호 아닌 이름 | `#basic`, `#hours` … |
| 시트는 저장소가 아니라 산출물 | 작성 중 데이터는 드라이브 `_session.json` |
| 담당자 기입란 보호 | `03_SheetSync.gs` `TAB_SPEC` — 적힌 칸만 쓰고 00·10 탭은 아예 안 씀 |
| 스냅샷은 전체 저장 | `_snapshots/v3.json` |
| 복원은 새 버전으로 | `restoreSnapshot_()` — 덮어쓰지 않음 |
| "모르겠어요"는 값이 아니라 상태 | `field()`의 상태 드롭다운 → 검토 화면 "상담 필요" 목록 |
| 로그인 없음 | 웹앱 `모든 사용자` 배포 |

## 알아두실 것

**자동저장은 10초입니다.** 앞서 3초로 잡았는데, Apps Script는 콜드 스타트가 1~3초라 3초 간격이면 저장이 계속 밀립니다. 단계를 이동할 때는 간격과 무관하게 강제로 저장하므로 데이터가 유실되지 않습니다.

**시트 동기화는 단계 완료 시점에만** 일어납니다. 매 저장마다 쓰면 API 할당량이 빨리 찹니다.

**동기화 실패가 입력을 막지 않습니다.** `apiSave`에서 시트 쓰기 오류를 삼킵니다. 사장님 입장에서 "저장이 안 된다"고 느끼는 게 더 나쁘기 때문입니다. 대신 최종 제출 때 전체를 다시 씁니다.

**메일은 Workspace 계정을 쓰세요.** 일반 계정은 하루 100통입니다.
